# Режим `сцена` — scene.json → построенная сцена

Твоя работа: превратить спецификацию в реальную сцену C4D, по которой можно анимировать не задавая вопросов. Ключевое слово — **иерархия**. Красота — дело режимов `материалы`/`свет`.

Провал этой роли выглядит так: аниматор ставит ключ на капсулу-ногу, а нога уезжает от тела, потому что она не под нулём. Или через неделю прокси меняют на нормальную модель — и вся анимация летит в мусор.

## Шаг 1. База документа

Скрипт `scripts/01-layout.py`, запуск `run.py --ladder scripts/01-layout.py`:
`timing(fps, length)` из scene.json + **лестница рендер-пресетов** + `tree()` + `done()`.
Fps выставляется **до** любых ключей: смена fps потом сдвигает всю анимацию.
Новый документ сохрани сразу как `PROJ + SLUG + ".c4d"` — раннер находит сцену по имени.

Лестница (c4d-core §4) — **после `timing()`** (билдер читает fps документа):

```python
render_ladder(engine="physical", res=(1920, 1080), f0=0, f1=length,
              gi=False, mb=True, dof=False,
              path=PROJ + "renders/final/" + SLUG)   # всё — из scene.json.output
use_rs("RS_draft")
```

Пресет RS_final сразу доводится до `scene.json.output.preset` по
`c4d-core/reference/render-presets.md` (выдержка камеры 1/60 — значением, traps.md).

В выводе билдера смотри поле `missing`: непустое — константы этой версии C4D
не совпали, допиши это в `pipeline.md`, лестница работает в деградированном виде.

## Шаг 2. Болванки

**Продукт / механизм / моушн** (нет `chars`, есть `hierarchy`): дерево нулей `ASM_*` из
`scene.json.hierarchy`, пивот каждого нуля — в функциональной точке (центр масс для
кувырка, ось хода штока, петля крышки), под нулём — примитив-болванка реальных габаритов.
Габариты взять из референса/CAD (чертёж, замер), не на глаз. Разнесённая схема
(сборка/разлёт) — смещения нулей, а не мешей.

**Персонажи** — ниже. Сначала загляни в библиотеку: `ls ~/c4d-assets/`. Есть готовый ассет с нужным контрактом — подгружай его (`asset_merge`, режим `ассеты`), а не строй заново.

Нет — строй прокси, это нормальный и правильный путь для превиза: сцена, камеры и тайминг доводятся на примитивах, модели приходят потом. Бери готовый билдер `~/.claude/skills/c4d-core/reference/biped.py` — читай файл, вклеивай функцию `biped()` в скрипт после прелюдии, вызывай на каждого персонажа из `scene.json`.

Иерархия, которую он строит (`h` — рост из `scene.json`):

```
CHAR_<id>_CTRL          нуль на земле — мировая позиция и поворот    ← аниматор двигает это
└ CHAR_<id>_root        нуль на высоте таза — покачивание, наклон    ← и это
  ├ CHAR_<id>_torso     капсула
  ├ CHAR_<id>_head      сфера
  ├ CHAR_<id>_armL_piv  нуль в плече                                 ← и это (мах руки)
  │ └ CHAR_<id>_armL    капсула, свисает вниз от плеча
  ├ CHAR_<id>_armR_piv / armR
  ├ CHAR_<id>_legL_piv  нуль в бедре                                 ← и это (мах ноги)
  │ └ CHAR_<id>_legL    капсула, свисает вниз от бедра
  └ CHAR_<id>_legR_piv / legR
```

Почему именно так:

- **Геометрия не анимируется никогда.** Все ключи живут на нулях. Захочешь заменить прокси на модель из Mixamo — подменяешь детей, анимация остаётся.
- **Пивот в суставе, меш со смещением вниз.** Если крутить саму капсулу, она вращается вокруг своего центра и нога отрывается от бедра. Пивот-нуль решает это без риггинга.
- **Персонаж смотрит в +X** (ось движения из c4d-core). Значит мах руки/ноги вперёд-назад — это канал **`rb`** (bank, поворот вокруг Z). Знак («вперёд» это + или −) зависит от сборки — аниматор проверит на первом рендере и при необходимости инвертирует. Зафиксируй проверенный знак в `pipeline.md`, чтобы это выяснялось один раз.
- **Пропорции.** Билдер считает всё от `h`, поэтому великан — это тот же вызов с `h=630`. Ничего не масштабируй через `scale` контроллера: масштабированный CTRL ломает интуицию по скорости и размерам теней.

Дай персонажам осмысленные силуэты уже здесь: контрастные персонажи должны различаться болванками — у тяжёлого шире торс и короче шаг относительно роста, у ловкого наоборот. Силуэт — единственное, что читается в общем плане.

### Цветовое кодирование болванок (обязательно)

Серые примитивы на сером фоне нечитаемы на контрольных рендерах — ни тебе, ни пользователю: «героя на f40 не различить» означает пересдачу этапа. Каждой болванке — плоский **светящийся** материал (канал Luminance, не Color: света в сцене ещё нет, обычный цвет отрендерится чёрным).

Раскладка:

| Что | Цвет |
|---|---|
| Герой | **оранжевый** (1.0, 0.5, 0.1) — самый тёплый в кадре, глаз находит его первым |
| Антагонисты / прочие персонажи | **синий**, каждому следующему свой оттенок (0.2, 0.4, 1.0 → голубее/фиолетовее) |
| Снаряды, интерактивный реквизит | **красный** (1.0, 0.15, 0.15) — должен читаться в полёте на любом фоне |
| Земля | тёмно-серый (0.25) |
| Окружение среднего плана | приглушённый зелёный (0.3, 0.45, 0.3) |
| Дальний план (горы, лес-стена) | серо-синий (0.35, 0.4, 0.5), темнее среднего |

Правила: один материал на персонажа целиком (не по конечностям — на общем плане это шум); окружение приглушённое, персонажи яркие — контраст «кто действует / где действует»; цвета записать в `pipeline.md`, аниматор и светорежиссёр читают рендеры по этой легенде. Материалы — служебные, с префиксом `MAT_blk_`: ассетист удалит их при подмене болванок одним фильтром по имени.

## Шаг 3. Окружение

- **Земля** — `SET_ground`, плоскость из `scene.json`. Обязательно: без земли не читается ни скорость, ни масштаб.
- **Полоса переднего плана** (`scatter` из `scene.json`) — камни/столбы вдоль трассы, разного размера, с разбросом по Z. Это то, что даёт ощущение скорости. Ставь через `random` в цикле, но **зафиксируй сид** (`random.seed(7)`), иначе повторный прогон скрипта пересоберёт сцену иначе.
- **Ориентиры глубины** — 2–3 крупных объекта далеко по +X, чтобы было видно, куда бежит герой.
- Всё окружение — под `GRP_set`, чтобы одним кликом гасилось.

Не увлекайся: 15–20 объектов достаточно. Лишняя геометрия только замедлит рендеры проверки.

## Шаг 4. Камеры

На каждый шот из `scene.json` — своя камера `CAM_<шот>`:

- позиция и фокусное из спецификации (`cam[c4d.CAMERA_FOCUS] = focal`)
- `look(cam, target)` из прелюдии — Target-таг, чтобы камера держала героя; для статичных постановочных кадров таг не нужен, ставь поворот руками
- все камеры — под `GRP_cams`
- активной сделай камеру первого шота: `activate("CAM_sh010")`

**Кадрирование — числом по всем кадрам**, не на глаз по одному: проекция габаритов главного
объекта в координаты кадра (NDC) на каждом кадре шота; главный объект ≤ 0.9 кадра по
высоте/ширине, если по плану он должен влезать («кейкап полностью помещался» — частая
правка). Печатай худший кадр и запас.

Проверь **высоту камеры** (если в сцене контраст масштаба): камера на высоте глаз человека (~160) рядом с объектом в 630 даёт совсем не тот масштаб, что камера на высоте 60. Низкая камера — крупный подавляет. Это решение режиссёра, оно должно быть в `shotplan.md`; если там его нет — спроси.

## Шаг 5. Визуальная проверка (не пропускать)

Рендер идёт через `RS_draft` — он активен с Шага 1 (тени выключены, это нормально:
вопрос этапа — геометрия и композиция, не свет). Отрендери **первый кадр каждого шота**
его камерой; если камеры уже движутся — сразу `playblast.py --stage blocking`:

```python
activate("CAM_sh010")
render_to(PROJ + "renders/layout-sh010-f0.png", 0, 960, 540)
```

`Read` каждый PNG и проверь по списку:

- [ ] Оба персонажа в кадре там, где задумано, не обрезаны случайно
- [ ] Контраст масштаба виден (если он в сцене есть) — крупный читается огромным, а не как «такой же, но побольше»
- [ ] Силуэты не сливаются друг с другом и с фоном
- [ ] Ничего не проваливается под землю и не висит в воздухе (частая ошибка: пивот капсулы в центре, значит нога уходит в землю на половину длины)
- [ ] Горизонт не режет героя по шее
- [ ] Передний план работает, а не загораживает действие

Нашёл проблему — правь скрипт в `scripts/` и прогоняй заново (скрипты идемпотентны, это безопасно). Не правь сцену «руками мимо скриптов»: потеряешь воспроизводимость.

Дальше: /c4d анимация
