# c4d-core — база 3D-пайплайна в Cinema 4D

Это не роль, а фундамент. Каждая роль читает этот файл на шаге 0 и подчиняется правилам ниже.

Пайплайн: вход — **`/c4d-plan`** (заменил `/c4d-director`): допрашивает пользователя, пишет план и **собирает под сцену** состав проходов с готовыми промтами в `prompts.md`. Исполнители — `/c4d-layout`, `/c4d-animator`, `/c4d-asset`, `/c4d-look`; какие из них и в каком порядке зовутся — решает план (персонажная сцена — полный набор с двумя световыми проходами; продукт-шот или статика — короче, без анимационных частей).

Состояние передаётся не через контекст сессии, а через файлы в папке проекта.

**Превиз идёт первым.** Сцена, камеры и тайминг доводятся на примитивах; ассеты подменяются после того, как постановка утверждена. `/c4d-asset` не блокирует никого — гейт перехода к нему описан в самом скилле. Контракт иерархии `CHAR_biped_v1` гарантирует, что подмена прокси на модель не тронет ни одного ключа.

## 0. Preflight — обязателен перед любым обращением к C4D

```bash
bash ~/.claude/skills/c4d-core/bin/c4d-preflight.sh
```

- `C4D_BRIDGE: down` → **СТОП**. Скажи пользователю: «Открой Cinema 4D → меню Extensions → Socket Server Plugin → Start Server», и жди. Не вызывай `mcp__cinema4d__*` вслепую — получишь таймауты и потратишь минуты.
- `C4D_APP: not running` → C4D вообще не запущен, сначала он.

Проверка живости после старта — один дешёвый вызов `mcp__cinema4d__get_scene_info`.

## 1. Пять правил, которые экономят часы

1. **Python-first.** Типизированные MCP-тулы — тонкие обёртки с багами (см. таблицу ниже). Всё, что сложнее «поставь куб», делай через `mcp__cinema4d__execute_python_script`.
2. **Один скрипт на шаг, не двадцать вызовов.** У плагина 30 с на главном потоке и большой оверхед на round-trip. Собирай всю фазу (вся иерархия / все ключи одного персонажа) в один скрипт.
3. **Скрипт сначала на диск, потом в C4D.** Пиши в `<проект>/scripts/NN-описание.py`, затем отправляй его содержимое. Так сцена воспроизводима: если C4D упал или пользователь что-то сломал — прогоняешь скрипты по порядку и получаешь ту же сцену. Это главный механизм надёжности пайплайна.
4. **Скрипты идемпотентны.** Всегда «найди или создай» (`N()` из прелюдии), никогда не «создай». Повторный прогон не должен плодить `Cube.1`, `Cube.2`.
5. **Смотри на картинку, а не на текст.** После каждой фазы — рендер в PNG и `Read` этого файла. Ответ «✅ Script executed successfully» ничего не говорит о том, читается ли кадр.

## 2. Надёжность MCP-тулов (проверено по исходникам плагина)

| Тул | Статус | Что делать |
|---|---|---|
| `get_scene_info`, `list_objects` | ✅ норм | быстрый чек живости и состава сцены |
| `add_primitive`, `create_light`, `create_camera` | ⚠️ работают, но бедные | ок для одиночного объекта; для иерархии — python |
| `modify_object` | ⚠️ | ок для позиции; свойства примитивов надёжнее через python |
| **`set_keyframe`** | ❌ **сломан** | сервер шлёт `property_name`, плагин читает `property_type`/`property` → свойство **всегда `position`**, а `value` обязан быть вектором. Ротацию/скейл им поставить нельзя. **Используй `key()` из прелюдии.** |
| **`render_preview`** | ❌ бесполезен | возвращает base64 прямо в текст ответа: картинку ты не увидишь, а токены сгорят. **Никогда не вызывай.** |
| `render_frame(output_path=…)` | ✅ так и надо | пишет PNG на диск → `Read` файла. Но **не умеет задавать кадр**: сначала выставь время через python, потом рендери. Ещё надёжнее — `render_to()` из прелюдии. |
| `create_material`, `apply_material` | ⚠️ | базовый цвет ок; отражения/шероховатость — python |
| `create_mograph_cloner`, `add_effector`, `apply_mograph_fields` | ⚠️ | работают, но параметры скудные; для точной настройки — python |
| `apply_dynamics`, `create_soft_body` | ⚠️ рискованно | симуляция + 30 с таймаут = подвисания. Для простой сцены не нужны |
| `save_scene`, `load_scene` | ✅ | сохраняй после каждой роли |
| `execute_python_script` | ✅ рабочая лошадь | ограничения ниже |

## 3. Ограничения песочницы `execute_python_script`

- Предопределены: `c4d`, `math`, `random`, `time`, `json`, `doc`. **Больше ничего не импортируется** — `import os`, `from os import`, `subprocess`, `os.system` забанены по подстроке, `eval(` и `exec(` тоже. Если такая подстрока встретится даже в комментарии или в строке — весь скрипт отклонят.
- Работа с файлами изнутри C4D — только через `c4d.storage` и `bmp.Save(...)`. Путей через `os.path` нет.
- Таймаут **30 с** на главном потоке. Тяжёлый цикл (сотни ключей) — режь на несколько скриптов.
- Возвращается захваченный `stdout`. **Печатай итог сам** — `print(json.dumps({...}))`, иначе получишь «executed but produced no output» и не будешь знать, что вышло.
- Все переменные верхнего уровня возвращаются как строки — включая функции прелюдии. Это шум в ответе, игнорируй.
- Ошибки приходят с полным traceback — читай его, там настоящая причина.

## 4. Прелюдия

Файл: `~/.claude/skills/c4d-core/reference/prelude.py`

Песочница создаётся заново на каждый вызов, поэтому прелюдию **приклеивай в начало каждого скрипта**. Она короткая и даёт:

- `find(name)` — поиск по имени во всём дереве
- `N(name, type, parent, pos, rot, scl)` — идемпотентное «найди или создай»; **углы в градусах**, конвертация внутри
- `key(obj, "px|py|pz|rh|rp|rb|sx|sy|sz", frame, value, interp)` — рабочая замена сломанному `set_keyframe`; углы в градусах
- `render_to(path, frame, w, h)` — рендер конкретного кадра в PNG
- `done(msg)` — `c4d.EventAdd()` + печать итога

Перед первым использованием на новой машине/версии C4D прогони `~/.claude/skills/c4d-core/reference/selftest.py` — он проверит, что все константы `c4d.*` на месте.

## 5. Соглашения о сцене

**Единицы.** C4D-дефолт — сантиметры. Человек ростом 180 = 180 юнитов. Держи реальный масштаб: от него зависят и свет, и глубина резкости, и физика.

**Кадровая частота.** Дефолт пайплайна — **24 fps**; другой fps — только явным решением в `scene.json`. Все покадровые ориентиры в скиллах (длительности шотов, периоды циклов, скорости в юнитах/кадр) даны для 24 fps. При другом fps пересчитывай: длительности и периоды × `fps/24`, скорости в юнитах/кадр × `24/fps`.

**Именование** (без него роли не найдут друг друга):

| Префикс | Что | Пример |
|---|---|---|
| `CHAR_<имя>_CTRL` | верхний нуль персонажа: мировая позиция + поворот. **Аниматор крутит только его и его дочерние нули** | `CHAR_odysseus_CTRL` |
| `CHAR_<имя>_root` | таз/корпус: покачивание, наклон | `CHAR_odysseus_root` |
| `CHAR_<имя>_<часть>` | геометрия | `CHAR_odysseus_legL` |
| `CAM_<шот>` | камера шота | `CAM_sh010` |
| `LGT_<роль>` | свет | `LGT_key`, `LGT_rim` |
| `SET_<объект>` | окружение | `SET_ground`, `SET_rocks` |
| `GRP_<группа>` | организационный нуль | `GRP_chars` |

**Правило контроллеров.** Геометрия никогда не анимируется напрямую. Всё висит под нулями. Тогда прокси-капсулу можно заменить нормальной моделью, не тронув ни одного ключа.

**Ось движения.** Договорённость пайплайна: герой бежит **вдоль +X**, камера смотрит примерно вдоль −Z. Направление на экране остаётся постоянным между шотами — иначе погоня «разворачивается» и читается как встреча, а не как бегство.

## 6. Папка проекта

```
~/c4d-projects/<slug>/
  shotplan.md      режиссёрский разбор: биты, шоты, тайминг    ← /c4d-plan
  scene.json       спецификация объектов и иерархии            ← /c4d-plan
  pipeline.md      лог: кто что сделал, что осталось            ← все роли дописывают
  scripts/         01-layout.py, 02-anim-run.py, …             ← все роли
  renders/         контрольные и финальные кадры
  <slug>.c4d       сама сцена
```

Общая на все проекты библиотека ассетов — `~/c4d-assets/<id>/` (`<id>.c4d`, `asset.json`, `build.py`, `thumb.png`). Ей владеет `/c4d-asset`, остальные роли только читают. Пути внутри python-скриптов передавай **абсолютными**: тильда в C4D не раскрывается, модуля `os` в песочнице нет.

Каждая роль на старте: `ls ~/c4d-projects/` → определить проект (или спросить), прочитать `pipeline.md` и свой входной артефакт. На финише: дописать в `pipeline.md` строку `## <роль> — <дата>` с тем, что сделано, что проверено рендером и что передаётся дальше.

### Схема scene.json

Контракт между планом и исполнителями: пишет `/c4d-plan`, роли читают. Поля,
которых требует сцена, заполняются числами; неприменимые блоки опускаются целиком
(у статики нет `length`, у сцены без персонажей — `chars`).

```json
{
  "version": 3,
  "fps": 24, "length": 150,
  "style": {"look": "lowpoly", "geometry_source": "procedural",
            "scale_note": "сантиметры, человек = 180"},
  "chars": [{"id": "hero", "h": 180, "build": 0.10, "speed": 24,
             "start": [-400, 0, 0], "notes": "ловкий: узкий торс, длинный шаг"}],
  "props": [{"id": "stone", "size": 30, "count": 3}],
  "set": {"ground": [4000, 2000],
          "scatter": {"count": 16, "zone": [[-500, 2500], [-300, 300]], "seed": 7},
          "depth_markers": 3},
  "shots": [{"id": "sh010", "frames": [0, 60],
             "cam": {"pos": [-600, 60, -420], "target": "hero", "focal": 32,
                     "move": "static"}}],
  "light": {"character": "низкое солнце",
            "key_dir": "сбоку-сзади относительно камеры"},
  "output": {"renderer": "Standard", "res": [1280, 720], "time_budget_min": 30}
}
```

Имена полей — закон: лейаут ждёт `chars[].h`, `set.scatter`, `shots[].cam.focal`
именно под этими именами. Нужно новое поле — правь эту схему здесь, а не изобретай
имя на месте.

**`version`** — счётчик правок: любая правка scene.json = `version + 1`. Промты
из `prompts.md` несут версию в шапке («scene.json vN», сразу после вызова скилла);
каждая роль на Шаге 0 сверяет её с текущей. Не совпала — промт устарел: СТОП, сначала
`/c4d-plan` (его Шаг 6, перевыпуск).

## 6b. Протокол общения ролей

Роли не разговаривают напрямую — они последовательны. Единственный канал между ними — `pipeline.md`. Поэтому канал формальный, а не «напишу в прозе, кто-нибудь прочитает».

### Правило чужих артефактов

Роль **никогда не правит вход, полученный от предыдущей**. Лейаут не редактирует `shotplan.md`, аниматор не перестраивает иерархию, свет не двигает ключи. Нашёл проблему в чужой зоне — заводишь заявку. Иначе теряется и авторство решения, и воспроизводимость скриптов.

**Единственное исключение — правки, утверждённые пользователем на приёмке (§7b), и только по масштабу:**

- **числовая** правка в рамках текущей постановки (фокал, позиция камеры, амплитуда маха, яркость) — исполнитель вносит сам в `shotplan.md`/`scene.json` с пометкой «кто, когда, по какой приёмке» и делает `version + 1`;
- **структурная** (тайминг, состав битов, внешность персонажа, состав проходов) — только через `/c4d-plan`: он правит артефакты и перевыпускает зависящие промты (его Шаг 6).

### Заявка назад

```markdown
### ЗАЯВКА → animator · открыта · от look · 2026-08-15
Кадры 96–104: стопа великана уходит под землю на ~20 юнитов.
Причина: амплитуда маха 48° при цикле 30 — нога длиннее, чем зазор.
Предложение: cyc=26 либо amp≤42.
```

Статусы: `открыта` → `закрыта` (починено, приписать чем) или `отклонена` (с обоснованием — «сознательный компромисс, оставляем»).

### Что делает каждая роль на Шаге 0

```bash
grep -n "ЗАЯВКА → <своя роль>" ~/c4d-projects/<slug>/pipeline.md
```

Все открытые заявки к себе — разобрать **до** начала новой работы. Роль не имеет права завершиться, оставив открытую заявку к себе без ответа: либо чинит, либо отклоняет письменно. Если заявка требует решения пользователя (например, «режиссёр, разрыв в шоте sh030 не читается — менять план или принять?») — спросить пользователя, а не решать молча за него.

### Уточняющие вопросы

У каждой роли есть свой блок «Уточнения» сразу после Шага 0. Правила общие:

- Спрашивать **до** работы, одним заходом, не больше четырёх вопросов, рекомендованный вариант первым.
- Спрашивать только то, что меняет результат. Если ответ уже есть в `shotplan.md`, `scene.json` или прозвучал в сессии — **не переспрашивать**, а зафиксировать как понял.
- Если пользователь уже описал всё сам — пропустить блок целиком и идти работать.

## 7. Цикл визуальной проверки (обязателен в конце каждой роли)

1. Через python выставить кадр и отрендерить: `render_to("<проект>/renders/<роль>-f<кадр>.png", frame, 960, 540)`
2. `Read` этого PNG — **посмотреть на него**
3. Сверить с чек-листом своей роли
4. Нашёл проблему — чинить сейчас, не передавать дальше

Для анимации — контактный лист: 4–6 кадров равномерно по диапазону, прочитать все, оценить читаемость движения по позам.

## 7b. Приёмка пользователем (обязательна в конце каждой роли)

Самопроверка из §7 — не приёмка. После неё роль **останавливается и сдаёт этап
пользователю**: показывает контрольные рендеры, перечисляет одной строкой каждое
отклонение от спеки и каждое решение, принятое по умолчанию, и спрашивает,
что поправить. Следующий этап не начинается, пока пользователь не принял текущий.

- Правки по итогам приёмки вносятся **в этом же проходе**, тем же исполнителем,
  и пересдаются. Не «учтём на следующем этапе».
- Правка, меняющая план, тянет правку `shotplan.md` / `scene.json` — по правилу
  масштаба из §6b: числовую вносит исполнитель с пометкой и `version + 1`,
  структурную — `/c4d-plan` с перевыпуском промтов.
- Молча перейти к следующему этапу — провал роли, даже если рендеры идеальные.

**Финальный просчёт анимации не запускать никогда.** Роль рендера настраивает
сеттинги, гоняет контрольный прогон на пониженном разрешении, оценивает время
кадра — и сдаёт настроенную сцену. Кнопку финального рендера нажимает пользователь
сам. Это его вычислительное время и его машина.

## 8. Если что-то сломалось

| Симптом | Причина | Лечение |
|---|---|---|
| Таймаут любого тула | плагин-сервер не запущен | preflight, попросить стартануть Socket Server |
| `Object 'X' not found` | опечатка или объект не в корне | `list_objects`, сверить имена; помни, что C4D добавляет `.1` к дубликатам |
| Скрипт «выполнен», но в сцене ничего нет | забыт `c4d.EventAdd()` | вызывай `done()` в конце |
| `Security: Banned keyword` | в тексте скрипта есть `import os` / `eval(` / `exec(` | переписать; проверь и комментарии |
| Ключи стоят, но объект не движется | ключи повешены на геометрию, а анимируется родительский нуль (или наоборот) | ключи только на `*_CTRL` и внутренние нули |
| Ротация «в 57 раз меньше» | C4D хранит углы в радианах | использовать `N()`/`key()`, они конвертируют из градусов |
| Рендер чёрный | нет света / камера не активна | проверить `LGT_*` и `bd.SetSceneCamera(cam)` |
