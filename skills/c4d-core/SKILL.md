# c4d-core — база 3D-пайплайна в Cinema 4D

Фундамент, не роль. `/c4d-plan` (план) и `/c4d` (исполнитель с режимами) читают этот
файл на шаге 0. Состояние между сессиями — в файлах проекта, не в контексте.

**Превиз первым.** Постановка, камера и тайминг доводятся на болванках; модели и
материалы — после того, как пользователь принял движение на плейбласте.

Инструменты лежат в `~/.claude/skills/c4d-core/`:

| Файл | Зачем |
|---|---|
| `bin/preflight.sh` | связь: C4D запущена, мост 18710, exec_python, список проектов |
| `bin/restart.sh [scene] [--force]` | перезапуск C4D с exec_python и ожидание моста |
| `bin/run.py` | **единственный способ выполнить код в C4D**: прелюдия + скрипт проекта |
| `bin/playblast.py` | черновое видео пачками, со звуком, открывается само |
| `bin/keysheet.py` | лист ключевых кадров движком финала — гейт перед финалом |
| `bin/final.py estimate/launch/watch` | замер, асинхронный финал в Picture Viewer, сборка |
| `bin/clipcheck.py` | % пересвеченных пикселей в PNG |
| `bin/c4d.py` | низкоуровневый клиент моста (68 команд, `reference/bridge.md`) |
| `reference/traps.md` | **ловушки C4D и моста** — грепать перед новым приёмом |
| `reference/motion.md` | принципы анимации, тайминг, easing, характеры, камера |
| `reference/render-presets.md` | пресеты рендера под случаи, цена эффектов |
| `reference/model-sources.md` | откуда брать новые модели, импорт, лицензии |
| `reference/prelude.py`, `renderladder.py`, `lib_solids.py`, `collision.py`, `lighting.py`, `assetlib.py`, `biped.py`, `runcycle.py` | библиотеки для скриптов |

## 0. Связь — перед любым обращением к C4D

```bash
bash ~/.claude/skills/c4d-core/bin/preflight.sh
```

Мост — плагин `cinema4d_mcp_bridge` на **127.0.0.1:18710** (TCP, JSON-строки). MCP-сервера
для C4D нет; всё идёт через `bin/run.py` (код) и `bin/c4d.py` (команды моста).

- `C4D_APP: not running` → `bash …/bin/restart.sh <проект>/<slug>.c4d` — запустит C4D
  с `C4D_MCP_ENABLE_EXEC_PYTHON=1` (слетает после перезагрузки мака) и дождётся моста.
- `EXEC_PYTHON: off` → тот же `restart.sh`; C4D закроется — **сначала спроси**, сохранена ли сцена.
- `мост занят` → идёт долгая операция или висит модалка: `run.py --wait 300`; не ожил —
  попроси пользователя глянуть на экран C4D; модалки нет — `restart.sh --force`.
- Перезапуск, закрытие C4D, остановка рендера в Picture Viewer — действия пользователя
  или с его согласия. `StopExternalRenderer` через мост не вызывать — вешает C4D.

## 1. Правила, которые экономят часы

1. **Скрипт сначала на диск, потом в C4D.** `~/c4d-projects/<slug>/scripts/NN-что.py`,
   выполнение — `python3 ~/.claude/skills/c4d-core/bin/run.py scripts/NN-что.py`.
   Сцена = прогон скриптов по порядку; порядок сборки записан в `pipeline.md`.
2. **Скрипты идемпотентны**: «найди или создай» (`N()`), исходные значения задаются
   явно (снятие трека/удаление блока не возвращает значение — traps.md).
3. **Один вызов ≤ ~45 с.** Лимит моста 60 с главного потока; таймаут не останавливает C4D —
   следующий вызов встанет в очередь. Дроби: персонаж/объект на вызов, кадр Physical на вызов.
4. **Смотри на картинку, а не на «executed».** Фаза кончается PNG/видео, которые ты
   открыл (`Read` PNG) и показал пользователю.
5. **Чат не стоит.** Всё дольше ~1 минуты (плейбласт > 60 кадров, лист Physical, финал,
   рестарт) — через Bash `run_in_background`, с одной строкой «что идёт и сколько ждать».
   Готовый результат открывается сам (скрипты делают `open`) и отправляется файлом.
6. **Версии вместо перезаписи.** Перед крупной правкой скрипта — копия `NN-что.vK.py`;
   отвергнутое — `*.rejected.py`; черновики `draft-vN.mp4`, листы `keys-vN.png`. Имена не
   различать регистром (macOS).
7. **Ловушка найдена — строка в `reference/traps.md`.** Не только в журнал проекта.

## 2. Раннер и прелюдия

```bash
R=~/.claude/skills/c4d-core/bin/run.py
python3 $R scripts/02-anim.py                         # прелюдия + скрипт
python3 $R --ladder scripts/01-layout.py              # + renderladder.py
python3 $R --lib lib_solids.py scripts/02b-check.py   # + библиотека из reference/
python3 $R --job '{"frames":[16,32]}' scripts/x.py    # JOB = {...} перед скриптом
python3 $R --code 'tree()'                            # разовый код
python3 $R --wait 300                                 # ждать мост после таймаута
```

Раннер сам: `import c4d, math, random, time, json`; `PROJ` (абсолютный путь проекта со
слешем), `SLUG` и `SCENE` (scene.json словарём — `open()` внутри C4D читает в ASCII) по пути скрипта; активирует открытый документ `<slug>.c4d` (иначе WARN);
вклеивает `reference/prelude.py`; печатает stdout/ошибку, подсказывает при таймауте.
**Тильда в C4D не раскрывается** — пути внутри скриптов строить от `PROJ`.

Прелюдия (`reference/prelude.py`): `W(o)` обход дерева, `find(name)`, `N(name, type,
parent, pos, rot, scl)` (углы в градусах), `key(o, "px|py|pz|rh|rp|rb|sx|sy|sz", f, v,
interp)`, `bake(o, ch, f0, f1, fn)` — покадровое запекание процедурного движения (easing,
пружины, баллистика из motion.md), `key_vis(o, f, on, mb=False)`, `clear_keys`,
`timing(fps, length)`, `look(cam, target)`, `activate(cam)`, `use_rs(name)`,
`render_to(path, f, w, h)` (без показа в PV — показ ронял C4D), `tree()`, `done()`.
Печатай итог сам: `print(json.dumps({...}))`.

Старый `selftest.py` проверяет константы на новой версии C4D: `run.py --ladder reference/selftest.py`.

## 3. Соглашения о сцене

**Единицы** — сантиметры, реальный масштаб (человек 180, MX-свитч ~1.5). **fps** — из
`scene.json` (дефолт 24; моушн под музыку часто 30). Ориентиры кадров в справочниках даны
для 24 fps: при другом — длительности × fps/24.

| Префикс | Что | Пример |
|---|---|---|
| `CHAR_<имя>_CTRL` / `_root` / `_<часть>` | персонаж: верхний нуль / корпус / геометрия | `CHAR_odysseus_CTRL` |
| `ASM_<деталь>` | нуль детали механизма/продукта (анимируется он, не меш) | `ASM_stem`, `ASM_cap` |
| `PROP_<имя>` | реквизит | `PROP_spear` |
| `CAM_<шот>` | камера шота; прицел — отдельный нуль `CAM_<шот>_aim` | `CAM_sh010` |
| `LGT_<роль>` | свет | `LGT_key`, `LGT_rim` |
| `SET_<объект>` | окружение | `SET_floor`, `SET_cyc` |
| `FX_<эффект>` | штрихи, вспышки, частицы | `FX_ring_hit1` |
| `GRP_<группа>` | организационный нуль | `GRP_chars` |
| `RS_<ступень>` | рендер-пресет лестницы | `RS_keys` |
| `TMP_*` | временное (плейбласт, проверки) — удаляется в finally | `TMP_clay` |
| `<имя>__<состояние>` | вариант состояния под тем же родителем (контракт — /c4d, режим ассеты) | `CHAR_x_head__smile` |

**Геометрия не анимируется напрямую** — всё висит под нулями; подмена болванки моделью
не трогает ни одного ключа. **Тейки** — только в конце: в не-Main тейке параметры света
заблокированы (traps.md).

## 4. Лестница рендер-пресетов и гейты

Четыре RenderData; создаёт режим `сцена` билдером `renderladder.py` из `scene.json.output`.

| | `RS_draft` | `RS_tex` | `RS_keys` | `RS_final` |
|---|---|---|---|---|
| Вопрос | геометрия, блокинг, тайминг | текстуры, палитра | свет, материалы, экспозиция на опорных кадрах | вывод |
| Как | Standard, AA Geometry, без теней, отражения вкл | Standard, AA Best, без теней | **клон RS_final**: тот же движок/свет/GI/AO, разрешение ×0.5, сэмплер preview, MB выкл | пресет из render-presets.md |
| Инструмент | `playblast.py` (640×360) | `render_to` | `keysheet.py` (сам синхронизирует с RS_final) | `final.py` |

**Гейты — обязательны, пропуск = провал режима:**

1. **Движение и камера принимаются по видео** (`playblast.py`), не по стоп-кадрам: силу
   удара и ритм на кадрах не видно. На плейбласте нет MB и финального света — сказать это.
2. **Лист ключевых кадров** (`keysheet.py`) — 5–8 опорных кадров движком финала в
   половинном разрешении + % пересвета каждого. Собирается:
   - после любой правки **камеры** (позиция, фокус, траектория, наезд) — свет с нового
     ракурса проверяется всегда, даже если «трогали только камеру»;
   - после правки света, материалов, пресета RS_final;
   - перед каждым финалом.
   Пересвет > 0.5 % на главном объекте или WARN — чинить до показа, не «потом в финале».
3. **Чистовой прогон** — `final.py launch --accepted keys-vN` только после того, как
   пользователь принял этот лист, и после `final.py estimate` (оценка времени показана).
   Запускаю сам, асинхронно в Picture Viewer, сразу `final.py watch` в фоне; пользователь
   получает видео по готовности. Правки во время прогона в него не попадут — предупредить;
   нужна правка — дорендер затронутого диапазона (`--range a-b`), не весь ролик.
4. **Перерендер только затронутого.** Правка на кадрах 75–162 → диапазон 75–162. Прежде
   чем перерендерить «из-за дёрганья» — проверить плеер/кодек (H.264 с B-кадрами в AE).

## 5. Папка проекта

```
~/c4d-projects/<slug>/
  shotplan.md   режиссёрский разбор                      ← /c4d-plan
  scene.json    числа: объекты, тайминг, key_frames, output ← /c4d-plan (+ числовые правки /c4d)
  prompts.md    проходы для /c4d                          ← /c4d-plan
  pipeline.md   журнал: порядок сборки, что сделано, цитаты пользователя, решения
  scripts/      NN-*.py (+ .vK / .rejected)
  renders/      preview/draft-vN.mp4, keys/keys-vN.png, final-vN/, final-vN.mp4
  making-of-stages/  материалы этапов + stages.md          ← --stage у инструментов
  reference/    референсы, CAD, модели
  sound/current.wav  звук для плейбластов (если есть)
  <slug>.c4d
```

Библиотека ассетов на все проекты — `~/c4d-assets/<id>/` (`<id>.c4d`, `asset.json`,
`build.py`, `thumb.png`).

**Мейкинг по умолчанию:** каждый принятый этап (блокинг, анимация, камера, свет,
материалы, финал) — с флагом `--stage <этап>` у playblast/keysheet/final: копия уходит в
`making-of-stages/NN-<этап>.*`, строка с датой — в `stages.md`. В `pipeline.md` у каждой
записи — цитата пользователя, по которой делалась правка.

### scene.json

Пишет `/c4d-plan`; `/c4d` читает. Неприменимые блоки опускаются.

```json
{
  "version": 3,
  "fps": 30, "frame_range": [0, 179],
  "style": {"look": "студийный продукт", "geometry_source": "procedural|downloaded|cad|library",
            "scale_note": "сантиметры"},
  "chars": [{"id": "hero", "h": 180, "states": [{"id": "face_smile", "frames": [40, 55], "what": "…"}]}],
  "props": [{"id": "switch", "size": 1.6, "pivot": "центр масс", "states": []}],
  "hierarchy": {"ASM_switch": ["ASM_bottom", "ASM_stem", "ASM_spring", "ASM_top", "ASM_cap"]},
  "set": {"ground": [4000, 2000]},
  "rhythm": {"bpm": 112.5, "beat_frames": 16, "accents": [16, 32, 48, 64, 80, 96]},
  "beats": [{"frame": 16, "what": "удар 1"}],
  "character": {"motion": "механический, хлёсткий", "camera": "простая: общий + наезд"},
  "shots": [{"id": "sh010", "frames": [0, 179],
             "cam": {"pos": [0, 30, -60], "target": "ASM_cap", "focal": 50, "move": "push-in"}}],
  "key_frames": [0, 16, 32, 48, 64, 80, 96, 179],
  "light": {"character": "каталог", "key_dir": "сверху-слева"},
  "output": {"renderer": "Physical", "preset": "PRODUCT_FAST", "res": [1920, 1080],
             "gi": false, "motion_blur": true, "shutter": "1/60", "dof": false,

```

`key_frames` — опорные кадры для листа: удары/акценты, вершины трюков, смены состояний,
первый и последний кадр каждого шота, самый тяжёлый по составу кадр. 5–8 штук.
`version` — +1 при любой правке; промты несут «scene.json vN».

## 6. Протокол работы

- **Журнал** `pipeline.md` — единственный канал между сессиями: запись `## <режим> — <дата> ·
  vN — «цитата пользователя»`, что сделано, чем проверено (файлы), порядок сборки, что дальше.
- **Правки после приёмки плана — режим `итерации`** (см. /c4d): слово пользователя и есть
  спека; числовые правки вносятся в scene.json с `version+1`; перевыпуск промтов и заявки
  не нужны. Структурная смена замысла (другой сюжет, другой стиль) — `/c4d-plan`.
- **Вопросы**: одним заходом, ≤ 4, рекомендованный первым, только то, что меняет результат.
  Если панель AskUserQuestion упала/не открылась — сразу текстом с номерами (пользователь
  отвечает «1, 3, 5»), не повторять вызов.
- **Идеи — меню с номерами.** Когда пользователь просит предложить или правка открытая
  («скучно», «вяло») — 3–7 вариантов с номерами и короткой ценой, не одно решение.
- **Отчёт после каждого шага — коротко**: что сделано, файл, что заметил сам, что спросить.

## 7. Приёмка

Каждый режим кончается показом результата (видео/лист), списком отклонений от спеки и
решений по умолчанию, вопросом «что поправить?» — и ждёт. Правки по приёмке — в этом же
режиме. Следующий этап без принятия текущего не начинается. Пользователь может сказать
«делай до конца без остановок» — тогда этапы идут цепочкой, но гейты §4 (лист перед
финалом) соблюдаются автоматически, а материалы этапов сохраняются.

## 8. Если что-то сломалось

| Симптом | Лечение |
|---|---|
| `bridge down` / connection refused | preflight → restart.sh |
| `timed out after 60.0s` | `run.py --wait`, затем дробить вызов |
| `exec_python disabled` | restart.sh (env слетел после перезагрузки) |
| скрипт «выполнен», в сцене пусто | не тот документ активен (WARN раннера) или нет `done()`/EventAdd |
| объект не движется | ключи на геометрии, а анимируется нуль (или наоборот) |
| рендер чёрный | нет света / камера не активна / GGX-материалы при выкл отражениях |
| кадр «размазан в кашу» | выдержка 1/30 вместо 1/60 (traps.md) |
| C4D упала посреди пачки | показ в PV/EventAdd на кадре — `render_to(show=False)` |
| всё остальное | `grep -n -i <слово> ~/.claude/skills/c4d-core/reference/traps.md` |
